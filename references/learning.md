# 逐章学习、测验与进度

## 选择章节

首次书写完成后给出简短目录，让用户选择；用户说“开始学习”却没有指定时，可推荐起始章，不能假装用户已经选定。用户指定函数、模块或问题时，映射到对应章节并直接处理问题，不强迫按书顺序走。选择章节后由用户决定陪读、答疑或测验。

回答默认短而直接。解释代码时先展示能回答当前问题的真实短片段并标明来源，再用具体过程说明输入是什么、变量或对象如何变化、哪个函数随后调用。跨越多个组件或分支时可用一张小表或流程图压缩关系；只有代码过长时才改用明确标注的伪代码或调用链，并保留真实路径与符号。发现理解错误直接指出并说明正确理解；简化类比明确标为简化，不能掩盖重要语义差异。

## 章节测验

用户已指定章节且要求出题时，核对该章正文及相关源码，生成 5～15 道题；默认 8 道。数量在范围外时说明范围并让其调整，用户明确要求改变此限制时尊重当次要求。题型与比例随内容决定，不要求凑齐不适合该项目的题型。

题目应有清晰输入、假设和范围，避免从缺失上下文猜代码。可包括：

- 选择：给定输入会进入哪条分支？
- 简答：为什么这里需要转换/缓存/校验？
- 推演：跨几个真实函数后数据是什么样子？
- 边界：错误在哪里产生并传给谁？

每题保存题号、章节、题目、关联源码、参考答案、关键评分点与必要解释。展示的 `测验/<章节>/<轮次>-题目.md` 只包含问题；`<轮次>-评分依据.md` 单独保存答案，并在展示前说明答案另存供答题后核对。新一轮用新文件，不能覆盖旧题和历史作答。

默认给出整套题并允许用户逐题或一次作答；用户要求逐题时遵循其节奏。先回答题目相关疑问，不因为查看了参考答案就标记通过。

## 评价与反馈

选择题按正确选项评价；开放题按照关键过程评分，接受等价表达，不按措辞一致性评分。每题采用 0~10 的打分制：主要根据用户所答和预期的答案是否贴合。题目有歧义时承认并修正，不能把题目问题算作用户错误。

反馈包含得分、回答中正确的部分、具体遗漏或误解、必要的源码依据。错题用一个小例子解释，再请用户复述或重试。补交答案作为新尝试保留；不编造未提交题目的得分。

测验小结区分已经理解的关键点与需要再读的代码，并推荐少量下一步动作。只对已回答题统计得分，同时显示作答数/总题数；未答题不算掌握，也不暗中补零生成“最终成绩”。

## 持久化约定

用人可读的 `学习进度.md` 保存状态，无需依赖特定会话系统。至少包含：

```markdown
# 学习进度

## 项目与教材版本
- 仓库来源：...
- 源码位置：...
- Commit / 分支或 tag：...
- 本地改动与快照说明：...
- 教程生成日期与覆盖范围：...
- 全书生成状态：进行中 / 完成

## 当前位置
- 当前章节：尚未选择 / 章节标识
- 当前活动：选章 / 陪读 / 答疑 / 测验
- 下次继续：具体待处理问题或题号

## 章节状态
| 章节标识 | 教材状态 | 阅读状态 | 测验记录 | 待解决问题 |
| --- | --- | --- | --- | --- |
| ... | 待生成/已生成/需核对 | 未开始/进行中/用户确认已读 | 测验文件链接 | ... |

## 学习记录
- 日期、章节、用户已确认的理解或待澄清的问题。

## 测验记录
- 日期、题目文件、作答记录、反馈文件、已答数量与得分。
```

需要详细答题记录时保存到 `测验/` 的独立 Markdown 文件并链接，不让进度文件无限增长。保留用户原回答与每次反馈；修改文件前读取现状，更新相关段落，避免覆盖用户自己的笔记。记录学习内容，不写入凭证或与学习无关的私人信息。

教程生成过程中，每章落盘后更新教材状态；中断后根据实际章节文件确认完成情况再续写。发现部分写入或正文缺失时标记待恢复，不能仅凭进度表宣布完成。

用户说“继续学习”时先读取进度与当前章节，简短说明停在哪，再继续未完成活动。核对源码 commit 和工作区变化；有变化时说明可能影响的教材，并按需求核对对应源码。无法确定影响范围时先把引用标为需核对，不能自行切换回旧版本或覆盖整本书。
